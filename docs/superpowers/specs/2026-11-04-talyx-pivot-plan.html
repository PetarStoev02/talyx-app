Talyx

Talyx becomes the place to tally agents.

One app: a roster of bots on the left, one chat on the right, Talyx as the manager bot. Built from the bots view of the old desktop app, restyled to Talyx, on a stock engine. This page is the plan: twelve pull requests, the screens, the flows, and the website update.

Owner Petar Stoev · design approved 4 November 2026 · source of truth docs/superpowers/specs/2026-11-04-talyx-agents-pivot-design.md in talyx-app

What ships

Keep

  • Bots as engine profiles, pinned tiles and project folders
  • One chat per bot; clarify and approval cards
  • The manager bot delegates to other bots through the engine tool message_agent
  • Group rooms hosted by the gateway, with today's history (6 rooms in the engine's state.db)
  • Routines (cron), SOUL, model and reasoning level, dictation
  • Providers exactly as today: the engine's config.yaml (your custom router on 127.0.0.1:20128 with its one combo, 9-route-provider), keys, OAuth logins. Untouched by the pivot; a Providers settings page lets you add more
  • The composer behaviour: +, model chip, reasoning level, mic, chevron

Drop

  • All of today's Talyx: sorting, watch folders, history, hotkey overlay, voice models, MCP server, Claude SDKs
  • Old desktop chrome: sessions list, command center, palette, starmap, capabilities browser, plugins, panes, updates, pets
  • The @assistant-ui transcript stack (24k lines); Talyx writes a small transcript of its own
  • Voice conversation mode, seven locale bundles, the cross-connection relay, the legacy desktop-run group mode
  • The old avatars; Talyx draws its own flat set

Settled

  • Same repo, same name, version 1.0.0
  • Builds for macOS, Windows and Linux, none of them signed or notarized; the download page says so and how to open them
  • Stack stays: Electron 44, React 19, Tailwind 4, shadcn, Zustand, electron-vite
  • Engine client vendored from tag v0.22.5, the installed release
  • Local gateway only in 1.0; remote machines are a later PR
  • English UI
  • Folders stored in the default profile's ui_meta, so every machine sees one layout
  • The engine's upstream name never appears in the app, the code or this plan: it is "the engine" (shared/engine/, EngineStatus, talyx-engine). Its real name lives only in engine.ts, the README and the install script
  • The manager bot (profile default) is called Talyx and wears the logo

PR 1 · Clear the deck

chore/pivot-remove-organizer1 day

Goal

Delete everything Talyx did before the pivot, so every later PR adds to an empty, building app. The old app is kept on the branch legacy/file-organizer and the tag v0.11.0-legacy (both pushed, 4 November 2026); the README links them.

Steps

  1. Remove src/main/domain/*, src/main/mcp/, src/main/infrastructure/{agent,ai-providers,brains,assistant,voice,workers} and their IPC handlers.
  2. Remove src/renderer/assistant/, src/renderer/src/features/*, the pages sort watch history search ask, the widgets tour welcome.
  3. Drop SQLite tables, migrations and better-sqlite3; settings stay a JSON file.
  4. Remove the dependencies: @anthropic-ai/*, @huggingface/*, @modelcontextprotocol/sdk, onnxruntime, pdf-parse, mammoth, xlsx, exifr, music-metadata, mailparser, chokidar, cheerio, phonemizer, thinking-orbs.
  5. Keep AppShell as an empty shell with one page, "Agents", that says "Nothing here yet".
  6. Rewrite CLAUDE.md and README.md for the new purpose, with a "Before the pivot" note pointing at legacy/file-organizer; bump to 1.0.0-alpha.1.

Done when

  • npm run build and npm test pass with the old tests removed
  • The macOS DMG opens to the empty shell
  • package.json has no dependency the new app does not use

Watch out

Delete in one PR, not gradually. Dormant code is the anti-goal.

PR 2 · Engine bridge

feat/engine-bridge3 days

Goal

Talk to the stock engine gateway from Talyx and prove one text round-trip with the default profile. No UI beyond a debug page.

Steps

  1. Main process: infrastructure/engine/engine.ts wraps the engine CLI (--version, gateway ensure --json per profile, ported from the old local-gateway.ts) behind an Engine interface. The upstream name lives only in that file, the README and scripts/talyx-engine. Never own or kill the gateway.
  2. Port the ticket minting (mintLocalGatewayTicket) through the profile's control socket; per-profile routing for the sockets.
  3. Vendor into src/renderer/src/shared/engine/ from tag v0.22.5: canonical-protocol.ts, client.ts, profiles.ts, sessions.ts, cron.ts, models.ts, config.ts, and the host.* calls the bots UI uses, as one plain module.
  4. Move the protocol tests that still apply (canonical-protocol.test.ts, canonical-profile-route.test.ts, clarify lifecycle).
  5. Debug page: pick a profile, send "ping", print the raw session events. Reconnect and replay must work.
  6. First-run state: engine missing shows the install line and a Retry button (screen 6). scripts/talyx-engine install installs the pinned engine release with pip.

Done when

  • A message to default returns a streamed reply through the vendored client
  • Quit and relaunch: the app attaches to the running gateway, no second process
  • README pins engine 0.22.5 and says how to re-sync the vendored folder

Watch out

The gateway listens on loopback and admits sockets by one-use tickets. Do not add a URL field; that is PR 12.

PR 8 · Avatars: Blocks

feat/avatars3 days

Goal

Reference: screen 7, Avatars below, rendered by the same SVG code. Every bot is a block in its own hue, drawn from the Talyx mark: an isometric block in three flat tones of one hue, no gradients. Shape × hue is the identity; a small face on the front face carries the state. Folders stack them and a group room is a pile of its members. Rendered in code, so it is crisp at 24, 44 and 64px and reacts to state.

Steps

  1. shared/ui/BlockAvatar.tsx: an SVG voxel renderer. Input: shape (6 named voxel sets: cube, tall, slab, stair, twin, tower), hue (12 picks, 30° apart), size, optional initial, state. Faces are the hue at three lightness steps (top 0.90, left 0.70, right 0.52 in oklch); offline drops chroma to 0.
  2. Face: straight strokes only, no curves. Eyes are two short ticks, the mouth one segment, in the hue's darkest tone, on the front face, drawn only at 40px and above (24px rows show the plain block). An expression is an angle: idle vertical ticks, flat line; working ticks tilted 35° toward the work, short line, plus a slow 1.6 s bob; waiting on you one tick plus a brow at 62°, an open angle for the mouth, plus the violet dot; offline ticks lying flat, chroma 0. The ticks rotate between states (200 ms), they never swap shapes. Selected changes nothing on the avatar, the row takes bg-accent.
  3. Motion, all CSS and SVG, transform and opacity only, off under reduced motion. No three.js: the roster draws 11+ avatars at once and WebGL canvases would cost a context each, blur at 24px and add about 600 kB for shapes that are six polygons. Where things move: roster row 24px nothing on the block, the dot fades in; pinned tile 44px blink every 4-6 s, working bob, hover lifts 2px, state change rotates the ticks; name pill nothing; details hero 64px blink, turns a few degrees toward the cursor by re-projecting the isometric angle (one number on pointer move, 200 ms ease), working bob; thread the sender's 24px block bobs next to "typing"; group pile the speaking member bobs, the others stay still; Look preview crossfades a shape or hue change and turns once.
  4. Group avatar: up to three member blocks side by side at 22-26px, one row; the name pill uses the same at 20px.
  5. Talyx (the default bot, the manager) is the logo as a block in black and white: the mark's silhouette in three greys (top #e9e9ee, front #2a2a30, side #141418), the logo's stripes in mid grey, and the same tick face in white. No hue: it is the one bot without a colour, which is how you tell the manager from the team.
  6. Identity data: ui_meta keeps shape and color as today; new values are the shape name and the hue index. Old values (a blobatar id, an hsl string) map once: hue from the hsl, shape from a hash of the id. Bots with no values get "Match the name": a hash of the name picks shape and hue, written back through profiles.configure.
  7. Look tab: a row of the 6 shapes, the 12-hue strip, "Match the name", a live 64px preview. No initials, no upload in 1.0. Faces on by default; one flag turns them off.
  8. Export: a 1024px PNG of the block for the profile asset, so the engine's other surfaces show the same avatar.

Done when

  • All 11 bots render as blocks with no two alike; the manager shows the logo
  • Working, waiting and offline states show in the roster and the pinned grid
  • Changing shape or hue in Look updates every size at once and survives a relaunch
  • Tests: hash-to-shape is stable per name; the voxel renderer draws every shape without overlap errors

Fallback

If blocks read as too playful after a day of use: Tiles, a rounded square in a pale tint with the initial in the same hue's ink. Same data, one renderer swapped.

PR 12 · Remote machines

feat/remote-gatewaylater, about a week

Goal

Use Talyx on one machine against bots on another over Tailscale. Decided after 1.0 is in daily use.

Options

  • SSH route, as the old desktop app does: the app opens an SSH tunnel and mints tickets on the far side. No backend config.

Not before

Risks

Protocol drift

An engine upgrade can break the vendored client. Pin 0.22.5, keep the client in one folder, keep its tests. Upgrading is a re-sync against the new tag, done on purpose.

The transcript

Written new, so fidelity starts low: text, tool lines, cards, images. Reasoning blocks and media come when needed. PR 4 is the one to watch for scope growth.

Two state libraries

The moved roster code uses nanostores and react-query; Talyx uses Zustand. Accepted now; fold into Zustand if it starts to hurt.

Mockups use Talyx's theme.css tokens (light and dark), shadcn Button, Dialog and Card geometry, the AppShell sidebar and settings switch, Geist, and the logo from TalyxLogo.tsx. The avatar shapes are placeholders until PR 8 (Avatars). Sample content to confirm before it is reused anywhere: the last-message previews, times, routine names, the room debate and the Q3 clarify card.
